## The project

Prediction markets (Polymarket and Kalshi) price macro events every day: Fed decisions, inflation
prints, elections and budgets, tariffs, wars. We turn these contracts into continuous daily indices
by country and theme (monetary policy, inflation, fiscal and political outcomes, trade and
tariffs, geopolitics) and use them in two currency strategies:

- **Strategy A (G10).** Only US cells have enough liquid contracts, so the primary rule is a dollar
  signal: US monetary and US fiscal news, with signs given by theory (hawkish news buys the dollar;
  the fiscal sign depends on whether the economy is in a monetary- or fiscal-dominance regime),
  drive a G10 basket against USD.
- **Strategy B (EM).** An emerging-market carry portfolio (1-month forwards and NDFs, freely
  floating currencies only) with a prediction-market geopolitical overlay that cuts exposure when
  escalation rises or a shock is confirmed. Benchmarked against the same rule driven by VIX.

Every rule was fixed before its backtest; variants and a posteriori additions are labelled as such.
Step-by-step walk-throughs: `notebooks/01_prediction_market_layer.ipynb` and
`notebooks/02_strategies_tests_results.ipynb` (executed). Figures: `results/figures/`.

## Reproduce

Three steps. Paths are relative; Python **3.13.13** (tested on Windows Server 2025; Linux/macOS use
`.venv/bin/python` in place of `.venv/Scripts/python.exe`).

**1. Environment.**

```
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

**2. Market data (Bloomberg and WRDS, licensed).** The only input not in this public repository:
the zip `230gb_market_data.zip`, sent to the instructor with the submission. Unzip it at the
repository root; it creates the two files the pipeline reads:

```
data/raw/market/priority1_market_data.csv        # FX spot, forwards, NDFs, risk series, 10-year yields
data/raw/market_qc/priority1_qc_flags.csv        # QC flags of the delivery (blanked observations)
```

Everything else (prediction-market panels, hourly FX, hand-coded inputs, code) is in the
repository. Without the zip, the same series can be pulled from a Bloomberg terminal (tickers
below) and WRDS, in the long format described under "Bloomberg".

**3. Run.**

```
.venv/Scripts/python.exe run_all.py
.venv/Scripts/python.exe -m pytest tests
```

`run_all.py` runs every stage in order: `pm` (classification, contract panels, theme indices),
`strategies`, `robustness`, `risk`, `figures` (figures, `results/site_data/`, `results/RESULTS.md`
and the interactive page `deliverables/index.html`). It rewrites `results/` and `deliverables/index.html`; compare with the
committed versions (`git diff --stat results deliverables`). Each stage can be run alone with
`--stage <name>` (`--stage site` rebuilds the page only). All parameters are in
`config/config.yaml` (fixed seed 230).

The prediction-market layer starts from the four panels in `data/processed/` (`pm_markets`,
`pm_daily`, `weekend_changes`, `hourly_index`), built from the raw trades tape (about 75 GB, not
shared). With the tape in place (`KAIROS_DATA_ROOT`, see "Data") the `pm` stage rebuilds them
first.

Expected runtime on the project machine (shared server):

| Stage | Runtime |
|---|---|
| `pm` | about 15 minutes from the shipped panels (about 20 from the raw tape) |
| `strategies` | about 1 minute |
| `robustness` | about 30 minutes (100 placebo draws per test) |
| `risk` | about 1 minute |
| `figures` | about 2 minutes |
| **Total** | **about 50 minutes** |

**Interactive HTML page (spec 11.2).** `deliverables/index.html` is one self-contained file (data, styles,
scripts and the Plotly library inlined, about 2 MB): open it in a browser, no server and no network
needed. It is generated by `src/report/build_site.py` from `results/site_data/` and the page sources
in `src/report/site/`; every number in its prose is formatted in Python from the data files, and
`tests/test_site.py` checks the page's data against `results/RESULTS.md`.

The notebooks are rebuilt and executed with `.venv/Scripts/python.exe notebooks/build_notebooks.py`.
The classification check against 200 hand-labelled markets
(`ai_log/classification/validation_sheet_*_human.csv`) is scored by the `pm` stage
(`src/pm/validation.py`; accuracy per field in section 1 of `results/RESULTS.md`).

- Forward tickers return **points**. Outright = spot + points / scale, bid with bid and ask with
  ask. Scales: 1 for KRW, IDR, PHP, TWD, COP, CLP; 100 for JPY, HUF, THB, INR; 1,000 for CZK;

  observations removed before use.
- No series is a 16:00 London fix: the execution lag this implies is under "Main conventions".

## Main conventions

- **Snapshot**: 16:00 London. A prediction-market value at t is the last trade strictly before
  the snapshot. Stored timestamps are UTC; DST is handled per date.
- **Execution**: FX prices are Bloomberg closes. A signal of day t trades at the New York close
  of t (G10, Latin America); at the Asian close of t+1 for Asian currencies (KRW in B).
- **FX excess return**: `rx(t+1) = s(t+1) - s(t) + carry(t)/252`, with `s` the log USD price of
  the currency and `carry = (s - f) x 12` from the 1-month forward or NDF.
- **Signals are causal**: volatilities, z-scores and filters use data up to t-1, or up to t where
  the spec says so.
- **Costs**: half the delivered 1-month forward bid/ask spread (causal 20-day median), doubled
  when VIX is above its expanding 90th percentile in B; sensitivity 0.5x to 3x.
- **Options and leverage**: no options. Leverage comes only from the 10% volatility target.
  Strategy A caps gross exposure at 3x capital and any pair at 30% of gross; Strategy B has no
  cap in its rule. Realised exposures and how often the caps bind are in `RESULTS.md`
  (sections 4 and 5) and `results/risk/leverage.csv`.
